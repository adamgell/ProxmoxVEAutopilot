## Integration boundary

Keep the existing `PgStore`, `Scheduler`, singleton orchestration authority, operation journal/outbox/projections, and shared VM reservation namespace. Registration contributes the immutable sixteen-stage manifest; it creates no attempt, lease, deadline, dispatch, callback session, or execution event. Never retrofit old generic OSDeploy rows into this manifest. All generic OSDeploy guards remain in force when new family methods arrive, including heartbeat, continuation, reaper, and raw command intake. Old three-stage native behavior remains unchanged.

The seven action mappings remain Clone→Clone, DiskCapacity→EnsureCapacity, ConfigurePe→ConfigurePe, StartPe→StartPe, PeEnsureStopped→EnsureStopped, ConfigureDisk→ConfigureDisk, and StartDisk→StartDisk. The other nine manifest stages acquire no PVE action. Derive order, operation keys, stage kinds, and dependencies from the existing `OsDeployStage::ALL`; do not create a parallel hand-maintained executor manifest. Only PeEnsureStopped admits the existing special grace dependency.

Add family-private transactional helpers beneath the existing types. Read-only reload can expose validated snapshots; snapshots and reconstructed dispatch values never confer a send capability. Do not add a public fixture constructor, `authenticated` flag, predecessor override, family bypass, arbitrary terminal-state input, or separate executor to make an incomplete vertical slice runnable.

## Transaction conventions

State-changing family transactions acquire the existing authority lock, existing `native:run` advisory lock, the sixteen operation locks in stable UUID order, then any worker lease lock. Claim/resume also need one family cap lock, placed consistently after run and before operation locks, so two runs cannot both consume the last slot. Reuse the existing authority and grant validation; do not create a second authority record. Discovery is unlocked and advisory. Every selected candidate is reloaded and checked under the complete lock order before writes.

Use DB `clock_timestamp()` after acquiring locks and again at the final decision/dispatch boundary. A transaction-start timestamp can become stale while awaiting locks. Host collection and guest/network work take place outside DB locks. On return, compare the current revision and re-evaluate freshness and eligibility; no caller clock or earlier permission survives these checks.

Every successful transaction commits journal decision/state events, attempt state, relevant immutable rows, outbox records produced by those events, and rebuildable projections together. An injected failure before commit leaves none of that transaction visible. Preserve existing registration's zero-journal behavior; execution is where new events begin.

## Absolute anchors and activation

Each scope is an immutable `(run, scope)` record containing the exact anchor operation/event, DB opened-at time, admitted policy seconds, and checked absolute deadline. Reload proves same-run event ownership and equality of `deadline = opened_at + budget`; a matching timestamp alone does not establish the anchor. All anchor events below are store-authored decision events, with a closed versioned discriminator and fixed reason. The naming below specifies semantics, not a new public event API.

| Scope | Transaction that creates it | Exact anchor |
| --- | --- | --- |
| One mutation budget for each of the seven PVE stages | First eligible activation of that stage | Its single `stage_activated` decision event and DB timestamp |
| PE registration | Original StartPe dispatch transaction | The `pve_dispatch_committed` event referenced by that immutable StartPe dispatch; same DB timestamp |
| PE completion | First selected successful PeRegister adjudication | That exact Satisfied decision event and evaluated-at time |
| Shutdown grace | First selected successful PeComplete adjudication | That exact Satisfied decision event and evaluated-at time |
| Shared full OS | Original StartDisk dispatch transaction | The `pve_dispatch_committed` event referenced by that immutable StartDisk dispatch; same DB timestamp |

InstallQga through VerifyOperational share the one full-OS deadline. StartPe and StartDisk retain their own mutation deadlines as well as opening their downstream scopes. Dispatch commit is the deliberately conservative anchor even if the external send/response is delayed or absent. Receipt capture, bootstrap contact, guest poll, process restart, lease reacquisition, and generation handoff create no replacement scope.

**Activation transaction:** validate the entire registration, current authority/cancellation, exact selected predecessor decision, stage capability availability, and cap. For a first PVE activation, allocate one logical attempt ID and one activation event and create its mutation scope, attempt binding, attempt, and short lease atomically. A non-PVE activation binds its attempt to the already existing required scope. The lease expiry is `min(DB now + short lease interval, absolute deadline)`; require a strictly positive interval. Stage activation must never allocate all sixteen attempts or open future phase budgets early.

An operation has at most one logical attempt under this initial contract. Its attempt ID, attempt number, scope binding, and deadline remain stable until terminal resolution, including safe unstarted reclaim. The existing generic `claim_operation_tx` cannot implement this: it allocates a new attempt and a five-minute deadline on every claim. Preserve that helper for existing users and implement the family behavior separately beneath the same scheduler.

If an inherited scope is already expired before first activation, no lease may be inserted and no budget may be restarted. The exact journal/state representation of this never-activated expiry still requires a schema/transition decision before that non-PVE path can be enabled; see the decision list below. Ordinary expired active stages record Unknown using their original attempt/scope.

## Durable PVE boundary and evidence reuse

**Evidence capture:** append typed observation evidence with its actual pre-append journal revision as `evidence_fence`, original observation times, operation/attempt identity, and the distinct workflow/PVE plan hashes. Repeating the same semantic key and digest returns the original event; conflicting bytes cannot replace it. The original fence remains `persisted event revision - 1`. Current aggregate CAS is a separate dispatch/decision input; never relabel old evidence to the latest revision. Generic EvidenceRecorded JSON is not admitted typed provenance merely because its shape matches.

**Dispatch transaction:** under the standard locks, reload the full plan, exact historical physical predecessors and durable semantic predecessors, original clone request, selected attempt/scope, and preflight event. Reconstruct and compare the complete request, including its own digest, against any supplied candidate. Require current generation, current grant owner/token, expected current revision, unexpired lease and deadline, no cancellation, and absence of an earlier dispatch. Re-run physical preflight at DB now. Commit the decision event, immutable full request/dispatch binding, any StartPe/StartDisk anchor, and any required stop-gate record together. Recheck deadline, lease, and freshness immediately before commit. Return a non-clone, non-serde permit only from this committed boundary; a reload never recreates it.

Only FakePve is admitted by the completed evaluator. The actual send occurs outside the transaction, at most once for that permit, through the existing provisioning path. A crash or lost response after dispatch commit makes the outcome uncertain even if the send did not occur. Recovery cannot assume an unsent command or reconstruct a permit. This boundary makes no cross-system exactly-once delivery claim. The service phase must additionally prove that its send path does not use a stale permit after loss of authority/lease/deadline; a DB transaction alone is not that proof.

**Receipt transaction:** an original worker may capture the exact original dispatch response after its lease/generation becomes stale. Acquire the authority row in the shared lock order but do not grant that worker current execution authority. Match the persisted operation/attempt, original generation, request/plan hashes, preflight event, dispatch revision/time, and receipt kind/UPID. First successful persisted capture chooses the server acceptance timestamp; equivalent replay preserves it, and a conflicting receipt fails closed. A caller-supplied earlier time is not accepted. Receipt capture neither sends nor finalizes nor extends the budget. If delayed capture makes earlier task evidence inadmissible, collect a fresh observation.

**Outcome transaction:** reconstruct the original request/dispatch/receipt plus current attempt identity and current authoritative lease/CAS. Persist the exact evidence-selected decision and its evaluated-at DB time. Before deadline, valid running-task/postcondition-pending advice can park; terminal advice records the operation/attempt transition and removes the lease/projection atomically. At `now >= deadline`, the result remains Unknown under the selected strict policy, including reconciliation. Late physical success can be retained as evidence but cannot be promoted with an extended deadline or historical evaluation clock.

Historical ownership reload is the one legitimate use of historical evaluation time: replay the exact *already selected* successful Clone decision through `ProvisioningCloneOwnershipV1::from_satisfied_clone`, then reconstruct each required baseline through `ProvisioningStageBaselineV1::from_satisfied` using its original context, evidence, deadline, and decision time. This validates existing proof; it does not adjudicate new late evidence. There are at most seven physical stages. PeEnsureStopped's physical predecessor remains StartPe even though its semantic predecessor is ShutdownGrace. No old `NativeCloneOwnership` conversion or public Deserialize constructor replaces this chain.

## Parking, due re-entry, and reaping

**Park transaction:** while holding a valid current evaluator lease, persist the exact Waiting decision/evidence, transition Running→Waiting, mark the same attempt Waiting, upsert a wait projection with park event/revision, next-check time and original scope, then delete the lease. All are atomic. Bound next-check time by the absolute deadline. Parked means there is no live worker lease; a long poll interval is not a worker failure.

**Due discovery:** scan both due wait projections and immutable expired scopes with unresolved bound operations. Journal reconstruction must rediscover parked work if the projection is missing/stale. An outbox notification accelerates discovery but is not necessary for correctness. Neither notification acknowledgement nor projection contents authorize a lease or a send.

**Resume transaction:** reload the selected park decision and current operation/attempt, recheck authority, cancellation, predecessor eligibility, actual due signal, deadline, cap, current CAS, and absence of an active lease. Allocate only a new lease token/owner/generation; retain the original attempt, deadline, dispatch, and receipt. Journal a distinct lease-reacquired decision. Start uses the legal Waiting→Running path, with no new `attempt_started` event. Stale/duplicate wakeups and replaced park revisions cannot acquire competing leases. An expired residual lease is first classified by the family reaper; it is not silently overwritten.

**Family reaper:** discover bounded candidates without row locks, then apply the standard lock order per candidate. Recheck expiry after obtaining locks. Consult immutable dispatch/exposure facts and the recorded evaluation activity, not just the existence of `attempt_started`.

| Locked facts | Required handling |
| --- | --- |
| Waiting, selected park event, no lease | Not a worker-expiry candidate; leave to due/deadline evaluation |
| Expired unstarted lease, no dispatch/exposure possible, budget remains | Private safe-reclaim transition to Pending, remove lease, preserve the same attempt/scope and journal why reclaim was safe |
| Interrupted evaluation proven read-only, no external dispatch/exposure, budget remains | Private repark transition to Waiting, same attempt/scope, reconstructible due projection |
| Dispatch committed, external action exposed, or send cannot be excluded | Unknown; remove lease, preserve original external identity and all evidence; no automatic attempt or resend |
| Scope expired at classification | Deadline Unknown for an activated stage; no safe-reclaim/resume even if a new short lease would otherwise fit |
| Terminal/cancelled or candidate changed while waiting for locks | No stale transition; reconcile only explicitly inconsistent projection/lease facts under a specified private rule |
| Historical generic OSDeploy without the admitted registration | Reject from family execution/recovery; preserve historical rows for the later compatibility decision |

An observer that crashes after a PVE dispatch falls into Unknown even when an original task receipt exists. A narrowly typed read-only reconciliation transaction may evaluate that same receipt/attempt under current authority, expected revision, no active evaluator lease, and the original deadline. Running-task advice remains Unknown; it does not silently restore Waiting or dispatch. Repeated observation before deadline can discover a valid terminal result. Exact due scheduling for this Unknown reconciliation needs an explicit projection discriminator; it must never select ordinary fresh dispatch work.

Reaper accounting separates safe unstarted reclaim, reparked read-only observation, and Unknown. Repeated reaping must append no duplicate decision and must not reset any anchor. Current-generation heartbeat may extend only the short lease, capped by its immutable scope; generic heartbeat stays rejected for OSDeploy. Authority handoff fences future decisions, while original response capture remains observational. Existing live leases are not silently reassigned on a generation change.

**Cancellation transaction:** under the same authority/run/all-operation/lease ordering, commit one immutable run cancellation proof plus the concrete stage decisions/lease and wait-projection changes specified by the future family cancellation policy. Every claim, resume, dispatch, outcome, and stop gate rechecks it. Capture can preserve original receipts/results afterward without granting continuation. Cancellation does not release VM/agent reservations or authorize external cleanup. Exact terminal representation for dispatched versus unexposed stages remains a transition-contract decision below.

## Amendment: concrete private transitions and handoff guarantees

Design choices below resolve items 1 and 3 above and refine item 5 for the next implementation brief; they are proposals for main's acceptance, not unbuilt behavior claimed as accepted. Checked against accepted `controller-domain/src/state.rs`, `transition.rs`, and `9abb501` foundation/scheduler/native source. The domain has no Cancelled state, treats Unknown as terminal, permits Running→Waiting and Pending→Blocked, and rejects Pending→Unknown and Leased→Pending through ordinary signals. Foundation permits a journal event with `attempt_id=NULL`, requires `attempt.deadline_at > started_at`, and requires `lease_expires_at > acquired_at` with `deadline_at >= lease_expires_at`. Preserve these constraints and existing native/generic policies.

Use a private `OsDeployTransitionProof` enum with variants `UnactivatedScopeExpired`, `ActivatedScopeExpired`, `ExpiredUnstartedSameAttempt`, `ExpiredReadOnlyEvaluation`, `CancelledUnexposed`, and `CancelledExposed`. Its fields and constructors stay within the OSDeploy scheduler module; constructors reload and check proofs under the standard locks. A private OSDeploy state append consumes this proof and emits the ordinary `decision_recorded` then, only if the state changes, `execution_state_changed` events. It must reuse existing journal/outbox/projection persistence semantics without broadening `DomainSignal` or the existing native policies. No public caller chooses a target state or supplies this proof.

Each decision carries a closed `action`, contract version 1, fixed reason, full workflow/stage hash, original state/revision, actual attempt ID or explicit null, DB evaluated-at, current authority generation, and exact referenced scope/anchor, cancellation, or lease-acquisition event IDs as appropriate. The state event references that decision ID. Allocate revisions consecutively in one transaction. Use deterministic operation-scoped semantic keys: `osdeploy:expire-before-activation:{scope}`, `osdeploy:reclaim:{lease-acquisition-event-id}`, `osdeploy:repark:{lease-acquisition-event-id}`, and `osdeploy:cancel:{run-cancellation-event-id}`. Equivalent re-entry returns the persisted outcome without new events; different facts for an occupied key fail closed. Never put worker credentials in these payloads.

| Private case | Exact admission and persisted result |
| --- | --- |
| Inherited deadline expired before activation | Require admitted non-PVE stage membership in the existing inherited scope, valid same-run anchor, Pending state, no attempt/binding/lease/dispatch/exposure, and DB now at/after its deadline. Commit `action=scope_expired_before_activation`, `reason=InheritedScopeDeadlineExpired`, attempt null, and private Pending→Unknown. Create no attempt or lease and do not backdate `started_at`. Expiry is scope adjudication and requires no fabricated predecessor success. Stages whose scope has not opened cannot use this rule. |
| Safe unstarted reclaim | Require Leased operation/attempt, matching expired lease, no `attempt_started` for that logical attempt, no dispatch/exposure or other possible-send fact, no cancellation, and unexpired original scope. Commit `action=lease_reclaimed_same_attempt`, `reason=LeaseExpiredBeforeStart`, private Leased→Pending; set the same attempt Pending with `completed_at=NULL`, delete exactly that lease, and keep the immutable attempt binding/times/number. Its next claim uses ordinary Pending→Leased but reuses this attempt and appends a lease-reacquired decision, not another activation. |
| Interrupted read-only evaluator | Require Running or Waiting operation, matching expired evaluator lease, durable current activity `read_only_evaluation` selected at lease start/resume, no dispatch/exposure or possible-send fact, no cancellation, and unexpired scope. Commit `action=evaluation_reparked`, `reason=ReadOnlyEvaluatorLeaseExpired`; use ordinary Running→Waiting or no state transition for Waiting. Set the same attempt Waiting, `completed_at=NULL`; write park/due projection and delete that lease. A resumed Waiting lease that has not started uses its lease-acquisition event as the activity proof. Missing proof or a prior dispatch excludes this recovery rule. |
| Cancel before exposure | For any nonterminal Pending/Leased/Running/Waiting/Cancelling stage, prove no immutable dispatch/exposed action/possible-send fact. Commit `action=stage_cancelled_unexposed`, `reason=RunCancelledBeforeExposure`; transition to Blocked through the existing domain rule. Keep attempt null for an unactivated stage; otherwise set its same attempt Blocked and `completed_at=DB now`. Remove its matching lease and wait projection. Blocked means the run cancellation prevented continuation; it is not an external failure claim. |
| Cancel with possible exposure | For a nonterminal stage with a committed dispatch, exposed guest action, or explicit possible-send fact, commit `action=stage_cancelled_exposed`, `reason=RunCancelledOutcomeUncertain`; private Leased/Running/Waiting/Cancelling→Unknown. Keep original attempt/dispatch/receipt/result, set the attempt Unknown and completion time, and remove matching lease/projection. A Pending stage with exposure is invalid persisted state and fails validation rather than being adopted. No intermediate Cancelling event or external stop is needed: the selected policy ends local continuation immediately while acknowledging uncertain external outcome. |

The new `osdeploy_decisions` representation must therefore allow an attempt-null variant, with a closed row check restricting it to `scope_expired_before_activation` or unactivated `stage_cancelled_unexposed`. Scope is mandatory for expiry; cancellation points to the immutable cancellation event and may lack a scope when none has opened. All activated decisions require the composite attempt/operation FK. Do not alter foundation attempt constraints or insert a dummy attempt. Reload additionally proves the attempt-null stage never activated and that its current terminal decision is the exact selected one. An unactivated ShutdownGrace expiry retains `InheritedScopeDeadlineExpired` and cannot authorize guarded stop: the existing exception requires an actual original grace attempt and its exact selected timeout decision. Mutable projection loss cannot remove this proof.

For reclaim/repark, original `started_at` and `deadline_at` never change; `completed_at` remains null because the attempt is still live logically. The immutable activity decision is a record of evaluator work, not authority to execute guest/PVE work. A dispatch transaction records its different activity atomically with dispatch. Expired Leased with an already started or inconsistent activity cannot take the safe-unstarted rule. Expired scope wins over both reclaim rules: activated Pending/Leased/Running/Waiting/Cancelling becomes Unknown through a separate private `ActivatedScopeExpired` proof referencing the original attempt/scope; this includes an attempt already safely reclaimed to Pending. Persist `action=activated_scope_expired`, `reason=PhaseDeadlineExpired`, semantic key `osdeploy:expire:{attempt-id}:{scope}`, set that attempt Unknown/completed-at and remove its matching lease/projection atomically. For ShutdownGrace, use the already selected `ShutdownGraceDeadlineExpired` reason and required PeComplete decision reference instead; other scopes cannot emit that stop-enabling reason. This never creates a new scope. Reconciliation remains the separately typed original-dispatch path; these rules never reopen a terminal Unknown.

Run cancellation creates its immutable run decision/row once, then adjudicates all sixteen stages and matching leases/projections atomically in stable lock order. Selection precedence is existing terminal decision, then an already expired applicable scope using the exact expiry rule above, then unexposed/exposed cancellation classification. Thus cancellation cannot turn an already elapsed active deadline into Blocked. Existing Satisfied/Failed/Blocked/Unknown/Conflicted states and their selected terminal decisions remain unchanged; a run cancellation record still fences every future continuation. Equivalent cancellation replay performs no new stage transitions. Original response/result capture remains observational after cancellation and cannot promote Unknown to Satisfied. Cancellation decisions report the exposure class, not delivery, rollback, or the physical stopping of an in-flight task.

Residual lease policy is precise: under authority/run/all-operation locks, first validate complete registration, selected attempt, and the lease's operation/attempt linkage. A terminal stage may have its matching residual lease and wait projection removed, even if that lease's wall-clock expiry is still in the future, after an `action=residual_lease_revoked`, `reason=TerminalLeaseRevoked` decision referencing the exact terminal decision and lease-acquisition event, keyed `osdeploy:revoke:{lease-acquisition-event-id}`. This revokes local store authority only; it does not prove the worker stopped sending. Do not rewrite the terminal attempt or state. A lease referencing another/unselected attempt, missing acquisition proof, or inconsistent terminal history fails validation with no cleanup. Cancellation of a nonterminal stage removes its validated matching lease inside the cancellation transaction, so it needs no second cleanup decision. A deliberately parked stage with no lease cancels normally. Parked plus unexplained live lease is an integrity error; Waiting plus a valid recorded resumed evaluator lease is legitimate and is revoked by cancellation. None of these rules apply to historical generic OSDeploy rows.

Required focused additions to the matrix: expire a Pending inherited-scope stage with zero attempts before/after and prove its null-attempt decision reloads; reclaim twice under distinct leases and prove one attempt plus stable times; expire that reclaimed Pending attempt; repark Running and resumed-Waiting separately; exercise all cancellation exposure/terminal classes with and without leases; race cancellation against dispatch/park/result capture; and reject foreign-attempt residual cleanup. No broad terminal-transition or repair API is introduced to test these cases.

### Authority check versus external send

A fresh DB authority/lease/deadline check is necessary but cannot fence PVE. The worker may pause after that check, authority can change, and the old worker can then send with still-valid transport credentials. Committing a generation with the dispatch, deleting its lease, expiring its deadline, or prohibiting network calls under DB locks does not close that interval. An already submitted PVE task can also continue after the caller stops. The accepted `transition_authority` updates the singleton row transactionally; it has no worker drain or external transport fence. Preserve that API's old behavior and do not describe it as a complete operational cutover.

For a **cooperative local service**, use one process-local send-admission gate shared by all of that service's mutation tasks and shutdown/handoff management. Close admission before draining, stop claim/resume/guest-exposure admission, cancel queued unsent work, and join every task that could consume an old permit. In-progress transport calls either finish with their original capture or remain durably uncertain; no retry is created. Only after drain proves there is no remaining local sender may that service perform/complete its coordinated authority handoff and allow the next writer to admit sends. Every restart begins with the gate closed, reloads current authority, and never restores old one-shot permits. FakePve barriers can prove this ordering for cooperative tasks in the tested process. A drain timeout means handoff readiness failed, not permission to assume quiescence.

That local gate does not coordinate another process/host, a suspended or partitioned old worker, legacy Python writers, independent mutation clients, or bytes already submitted to the network. For cross-process production cutover without verified transport-side fencing, require an explicit cutover gate: account for and stop/disable all old mutation-capable workers (including Python), establish they cannot restart/send, reconcile outstanding ambiguous requests/tasks, and then enable the new writer under the one existing authority. If worker quiescence cannot be established, do not enable the new writer. Merely waiting for DB leases to expire is insufficient.

A stronger stale-sender guarantee would require the actual mutation ingress to atomically reject an old generation/capability for each request, including queued stale requests. Current proof has established no such PVE-side facility; do not claim one or add a separate executor in this phase. Credential/network revocation may help an explicitly approved operational cutover but must be verified at the mutation endpoint and does not cancel already accepted tasks. Exact deadline enforcement at the remote acceptance instant likewise cannot be guaranteed by a prior local clock check. The implementable guarantee here is locally gated send initiation plus strict durable outcome deadlines, preserved ambiguity, and no resend; production readiness still requires the broader single-writer/cutover evidence and external authorization.
