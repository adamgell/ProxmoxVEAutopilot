# Accepted Clone effect before receipt journal

`accepted_effect_without_journal_receipt_stays_unknown_after_worker_loss` in `crates/operation-controller/tests/postgres_fixture_workers.rs` exercises the window where the fixture daemon durably accepts Clone but PostgreSQL has no receipt.

Worker A claims and starts the operation, commits dispatch, and consumes its submission permit. A narrowly scoped test-process pause immediately after submission keeps the returned receipt in that worker's address space before the receipt journal call. The supervisor independently reads the daemon's accepted effect, then reads PostgreSQL to verify the original attempt, Running state, durable dispatch and absent receipt. Only then does it kill worker A. The effect observation must precede the PostgreSQL read to avoid mistaking a legitimate earlier snapshot for missing dispatch.

Worker B reconstructs the operation using a fresh PostgreSQL connection and reads the exact original effect with submission sequence one. Existing scheduler APIs refuse claim/resume while the first lease is live. Worker B observes actual database lease expiration without altering lease policy, reaps the operation to Unknown, and requests reconciliation using supervisor-collected evidence. The scheduler's existing missing-task-receipt guard returns `Idle`, preserving Unknown, the absent receipt, and the same revision. The fixture daemon restarts from its ledger before final reconciliation checks. Final assertions preserve the original attempt and effect, keep the database attempt count at one, and refuse replacement claim/resume.

The pause is defined only inside the ignored worker test entry point; it adds no production fault flag or runtime capability. This proof establishes safe uncertainty in the receipt-loss window. It does not repair a missing receipt, execute the complete controller entry point, or establish successful reconciliation from complete IPC task observations. Collection remains supervisor-assisted using the existing native scenario.

Validation on macOS: `cargo test --offline --locked -p operation-controller --features fixture-ipc --test postgres_fixture_workers worker_loss -- --nocapture` passed both worker tests together (2 passed, 36 filtered out), including both child recovery checks. Strict Clippy for the integration target and workspace formatting passed. An initial run exposed the observer ordering race described above; a subsequent run confirmed the missing-receipt path returns `Idle`, as required by the existing scheduler guard. The final assertions cover both behaviors explicitly. All infrastructure used by this test is owned local PostgreSQL and synthetic fixture IPC.
